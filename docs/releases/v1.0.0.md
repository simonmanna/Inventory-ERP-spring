## Upgrade / cut-over

- From POS-CAFE (Nest): `docs/OPERATIONS.md` §5 — same database, same `.env` secrets; Flyway baselines at V2 and adds
  Spring-only tables. Existing JWTs, refresh tokens, PIN hashes, MFA secrets and Android device tokens stay valid.
- Between Spring versions: `scripts/upgrade.sh` / `scripts/upgrade.ps1` (pre-upgrade dump, automatic image rollback).
- Backups: set `BACKUP_ENCRYPTION_PASSWORD`, a second destination, and `PG_BIN` to PostgreSQL **16** client tools.

## Deviations from the Nest behaviour (pending owner approval)

- Backup restore checks count Flyway migrations (`flyway_schema_history`) instead of `_prisma_migrations`; the backed-up
  database comes from the Spring datasource settings; `.env` capture looks in `.`, `backend/`, `../`.
- Inventory `lowStock` filter, task date-only `dueDate`, DMS A4 PDF via OpenPDF (listed in each module spec).

## Same as Nest, kept on purpose (candidates for 1.0.x fixes)

- HR: leave-balance adjustments add by string concatenation (`2.5` + `1` → `2.51`); fractional overtime hours make
  payroll calculation fail (Int column); attendance summary / register windows start 30 / 6 days before `from`.
- POS: `/menu/public/*` needs a JWT; `/pos/tables/:id/split-bill` always 409; `/pos/tabs/:id/split/equal` 500;
  online-order status PATCH rejected by the whitelist.
- Auth: a replayed rotated refresh token is refused but does not revoke its successor.
- Procurement: PO search → 500; inbound non-RTV debit note never balances.

(HR and orders on, throttling off for the load runs).

| Check | Result |
|---|---|
| `./gradlew build` | green — 394 tests (1 skipped: restore IT needs `pg_restore` 16 locally) (unit + Testcontainers integration), Spotless, ArchUnit/Modulith, JaCoCo ratchet |
| Application coverage (JaCoCo, `*.application`) | 74 % lines overall, 57–92 % per package |
| Browser smoke (Playwright, 31 web pages incl. POS, KDS, HR, orders, reports) | zero console errors; only `/hr/team` answers 400 "login not linked" for the admin without an employee record (same as Nest) |
| DR drill (`node scripts/dr-drill.mjs`) | PASSED — 1.15 MB encrypted full backup, 302/302 tables restored into a scratch DB, trial balance identical |

| Offline replay | `SyncInventoryReplayIT` (5) + `SyncIT` (8) green |
| Parity harness (`contract-tests/run.mjs`) | **not run locally** — needs a built Nest reference + two seeded databases; run before cut-over (`docs/TESTING.md`) |

Checkout latency (`tools/perf/checkout-smoke.mjs`, 30 s, 0 errors in every run):

| Terminals | p50 | p95 | Throughput |
|---|---|---|---|
| 1 | 199 ms | 342 ms | 4.6 / s |
| 10 | 325 ms | 527 ms | — |
| 50 | 1,235 ms | 1,790 ms | ~26 / s |

The BUILD_GUIDE bar (p95 ≤ 150 ms) is **not met** on this setup. A checkout runs ~400 SQL statements in ~34
transactions (stock posting, ledger, audit, outbox, settings lookups); on Docker Desktop COMMIT is 87 % of database
time. Async commit for outbox marks and fire-and-forget audit rows halved the p95 at 10 tills (1,023 → 527 ms).
With `synchronous_commit = off` server-wide (measurement only, not recommended) 1 till reaches p95 170 ms. Re-measure
on the production host (Linux, local SSD) before go-live; next step is fewer transactions per checkout (batch
settings reads, fold the stock-posting job into the sale transaction).

- Checkout p95 above the 150 ms bar on Docker Desktop (see "Verification").
